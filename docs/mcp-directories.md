# MCP 目录与程序分发

本机 MCP 支持旧式 `mcp/<id>.json` 和目录式 `mcp/<id>/mcp.json`。
同一个 ID 不得同时使用两种布局。目录内的程序用 `./bin/program.exe` 等相对路径，
始终相对配置目录解析；不是宿主当前工作目录。工作目录可为 `.` 或 `./子目录`。
仅加载配置不启动程序，现有 MCP 连接、权限、发现和进程回收流程继续生效。

目录式分发使用 `mdo.extension.v2` 和 `mdo.mcp-template.v2`，最低构建号 70000057。
客户端直接打包选定 MCP 目录，运行文件仍放在该目录，没有独立制品登记或安装脚本。
配置经现有脱敏导出生成公开模板；私密值、设备路径及运行日志不进入模板。
作者应检查公开启动参数、每个分发文件及许可证。`mcp.json`、`template.json` 不作为
附属文件打包；根目录的隐藏目录、`cache`、`logs` 不打包。

沿用现有扩展上传与审核协议，每个文件记录相对路径、原始字节数、SHA-256、
0644/0755 模式及 `identity`/`zlib` 编码。客户端自动压缩程序，无需作者预制 ZIP。
包 JSON 仍限制 100 MiB，MCP 目录最多 1024 个文件、128 MiB 原始内容、单文件
64 MiB；压缩输出严格限制在声明的原始大小。拒绝越界、大小写别名、文件/目录重叠、
缺失入口、错误摘要及符号链接。一个包可声明多平台变体，当前 Cua 只声明 Windows。

安装会在 `mcp/<id>/` 写入公开 `template.json`、完整程序目录，以及默认停用的
本机 `mcp.json`。私有连接配置不作为不可变程序文件登记，更新保留其设备参数。
程序更新或移除前断开对应 MCP，避免 Windows 正在执行的文件被覆盖。
安装计划先于写入；压缩载荷和旧文件进入现有恢复日志，失败恢复原文件与登记。
卸载移除未修改的分发文件，保留并停用本机配置；本机修改过的文件保留。
不自动安装 Python、运行安装钩子或授予现有浏览器配置访问权限。

验证：`python tests/test_mcp_directory_runtime.py`、
`python tests/test_mcp_directory_install.py`、
`python tests/test_ecosystem_package_v2.py --host <匹配 SDK 的 xs.exe>`。
这些测试直接编译本目录源码，不复制应用；测试用数据位于本目录 `.build/`。
